# План рефакторинга `src/bin/cnc_emulator/state.rs`

## Цель

Разделить состояние эмулятора, обработку API-команд и обновление симуляции по ответственности, сохранив `Emulator` и существующие точки входа (`new`, `handle`, `tick`) без изменения вызывающего кода. Поведение фиксировать тестами до и после каждого этапа.

## Предлагаемая структура

Рядом с `state.rs` создать каталог `state/`:

- `state/commands.rs` — обработка API-запросов и команды: `handle`, проверки допустимости движения.
- `state/tick.rs` — временное обновление симуляции: шпиндель, перемещения, homing, jog и выполнение программы.
- `state/coordinates.rs` — выбор координатной системы, установка рабочего нуля и сохранение смещений.
- `state/tests.rs` — тесты, которые проверяют само состояние и поведение API.
- `state.rs` — структура `Emulator`, конструктор и подключения модулей.

Оставить в `state.rs` небольшие общие методы и поля, нужные нескольким модулям. Не расширять видимость за пределы текущего `pub(super)` без необходимости.

## Этапы

1. **Зафиксировать текущее поведение.** Запустить `cargo test --bin cnc-emulator` и `cargo check --all-targets`. Отдельно отметить существующие тесты для лимитов, загрузки программ и комментариев.
2. **Вынести координатные операции.** Перенести `select_coordinate_system`, `set_selected_work_zero` и `persist_coordinate_offsets` в `state/coordinates.rs`. Проверить выбор систем, сохранение и ошибочные случаи.
3. **Вынести обработку запросов.** Перенести `handle` и связанные с обработчиком API вспомогательные методы в `state/commands.rs`. Сохранить сигнатуру `Emulator::handle`.
4. **Вынести цикл симуляции.** Перенести `tick` в `state/tick.rs`; сохранить текущий порядок обновления шпинделя, перемещений, homing, jog и выполнения программы.
5. **Разнести тесты по ответственности.** Переместить тесты лимитов в тесты состояния, а тесты загрузки программы — к обработке команд. Не дублировать фабрику эмулятора: при необходимости создать общий тестовый helper под `#[cfg(test)]`.
6. **Удалить устаревший код и проверить сборку.** Убедиться, что не осталось дублирующих методов, затем выполнить форматирование, тесты и проверку всех целей.

## Важные детали Rust

Для `state.rs` с соседним каталогом подключать дочерние файлы явными путями, например `#[path = "state/commands.rs"]`, чтобы избежать неоднозначности расположения модулей. Методы можно реализовать в дочерних модулях через дополнительные `impl Emulator`; поля оставить с текущей видимостью, если дочерним модулям её достаточно.
