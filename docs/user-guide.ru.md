# CNC UI — Руководство пользователя

CNC UI — это панель управления станками с ЧПУ с двумя взаимозаменяемыми
интерфейсами: десктопным приложением (Tauri) и тем же интерфейсом, который
встроенный веб-сервер отдаёт любому браузеру в сети. Приложение работает с
контроллерами FluidNC по сети, с платами GRBL 1.1 через последовательные
COM-порты и поставляется с полноценным программным эмулятором, чтобы освоить
интерфейс безопасно, без оборудования.

> **Безопасность прежде всего.** Это приложение не является средством
> безопасности. Перед запуском физического станка самостоятельно проверьте
> подключение, концевики, подачи и сам программу в режиме холостого прогона.
> Последовательные команды — не аварийный стоп: всегда имейте доступ к
> аппаратной кнопке E-stop станка.

## 1. Начало работы

### 1.1 Десктопное приложение

Сначала запустите эмулятор (если не подключаетесь к реальному оборудованию):

```bash
cargo run --bin cnc-emulator          # читает config/emulator.yaml
cargo run --bin linuxcnc-ui           # окно приложения
```

Десктоп автоматически подключается к эмулятору через локальный сокет
(`/tmp/linuxcnc-ui-emulator.sock`, переопределяется `CNC_EMULATOR_SOCKET`).

### 1.2 Веб-интерфейс

```bash
cargo run --bin cnc-web               # сервер на http://0.0.0.0:8080
```

Откройте `http://<host>:8080` в браузере. Параметры (переменные окружения):

| Переменная | Значение | По умолчанию |
|---|---|---|
| `CNC_WEB_ADDRESS` | адрес:порт привязки | `0.0.0.0:8080` |
| `CNC_UI_AUTH_USER` + `CNC_UI_AUTH_PASSWORD` | включить HTTP Basic-авторизацию | выключено |
| `CNC_UI_AUTH=on` / `off` | принудительно включить (случайный пароль пишется в лог) / явно выключить | авто |
| `CNC_UI_LOG_DB` | расположение базы SQLite | `~/.local/state/linuxcnc-ui/messages.sqlite3` |
| `CNC_EMULATOR_SOCKET` | путь сокета эмулятора | `/tmp/linuxcnc-ui-emulator.sock` |

Авторизация защищает весь веб-интерфейс одной парой логин/пароль; браузер
показывает окно входа при первом запросе. Оставьте учётные данные незаданными
для доверенной лабораторной сети, задайте их в любой общей сети.

## 2. Выбор станка

Чип состояния подключения в шапке открывает **диалог «Станки»**. Список всегда
содержит:

* локальный **эмулятор** (пока запущен процесс эмулятора);
* платы **GRBL**, найденные на последовательных портах (`ttyUSB*`, `ttyACM*`,
  `ttyS*`, `COMn`);
* контроллеры **FluidNC**, найденные в сети (пробы WebSocket :80 и Telnet :23
  с подтверждением идентичности `$I`), а также платы FluidNC, подключённые по
  USB (распознаются по загрузочному баннеру; если баннер сообщает Wi-Fi-адрес,
  станок отображается под своим сетевым идентификатором).

Станки с несколькими доступными интерфейсами сгруппированы: небольшой заголовок
называет физический станок, а его транспорты висят ниже как отступленные
варианты — нажимайте тот вариант, через который хотите работать. Нажатие на
любую строку мгновенно переключает backend; загруженная программа и траектория
перезагружаются на новом станке. Кнопка обновления запускает полное сканирование
заново; результаты сохраняются между перезапусками.

Пробы GRBL поднимают DTR/RTS и сбрасывают Arduino-платы — во время подключения
собственный порт станка не сканируется повторно. Скорость по умолчанию 115200
(`CNC_GRBL_BAUD=9600` для старых плат).

## 3. Панель POSITION

* Кнопки **WPOS / MPOS** переключают колонки рабочих и машинных координат;
  кнопки остаются выровненными над своими колонками при любой ширине панели.
* Выпадающий список **G54…G59.3** выбирает активную систему рабочих координат.
* Каждая строка оси показывает значение, кнопку **обнуления** и кнопку
  **home**. На 5- и 6-осевом станке каждая конфигурированная ось получает свою
  строку (панель прокручивается, если строки не помещаются по высоте).
* **Обнулить все** записывает текущую позицию как рабочий ноль выбранной
  системы; **Исходное положение** запускает процедуру возврата в исходное положение.
* **Телеметрическая полоса** под кнопками показывает живые данные движения:
  текущую подачу с активным модальным режимом (`Jog`, `G0`, `G1`, `G2`, `G3`,
  `Homing`), обороты шпинделя и **лампы СОЖ** (Туман M7 / Поток M8 светятся,
  когда включены).
* Нажатие на значение рабочей координаты открывает диалог точного ввода позиции.

## 4. Панель JOG

Два стиля управления (переключаются кнопками в заголовке): **диск** и
**клавиши**. Два режима движения: **дискретный** (нажатие = один шаг) и
**непрерывный** (удерживать = двигаться до отпускания/стопа).

### 4.1 Диск

Круговой диск покрывает восемь направлений; кольца кодируют четыре размера шага.
Нажмите на сектор для шага, или удерживайте и ведите в непрерывном режиме.
Поворотные оси **A/B/C** появляются колонками справа от Z, если станок их
сообщает; их заголовок показывает единицу (`°` для угловых осей, `mm` для
линейных). Кнопки шага несут фиксированные расстояния; колонки Z и поворотных
осей разделят переключатель дискретный/непрерывный.

### 4.2 Клавиши

Кнопки X/Y/Z с диагоналями, Z±, а при наличии конфигурации — колонки A±, B±, C±
плюс выбор шага для каждой поворотной оси (те же оси, что показывает диск).

### 4.3 Подачи

Между диском и секцией шпинделя расположен **ряд подач по осям**: XY, Z и каждая
поворотная ось имеют свою скорость jog. Кнопка открывает список пресетов
(формируется из максимальной скорости оси так же, как пресеты шпинделя) плюс
строку **редактирования** для произвольного значения. Значения сохраняются
локально и отправляются контроллеру; легаси-кнопка (иконка ползунков) по-прежнему
редактирует XY/Z и общую скорость поворотных осей.

Квадратная кнопка **Стоп** (центр диска и клавиши) отменяет всё движение jog.

## 5. Шпиндель

Слайдер RPM, кнопка пресетов (шесть равноотстоящих значений между
сконфигурированными минимумом и максимумом, плюс ручной ввод) и кнопки запуска
по/против часовой стрелке. Нажатие активной кнопки направления останавливает шпиндель.
Панель зеркалит заданные и фактические обороты из телеметрии.

## 6. Программа и 3D-вьюер

* **Загрузите** файл G-code из панели Files или из тулбара вьюера; программа
  проверяется, отправляется контроллеру и рисуется как траектория.
* Легенда вьюера объясняет цвета линий: серый пунктир = быстрый G0, сплошная =
  подача G1, дуги = G2/G3. Уже пройденная часть траектории затемняется по мере
  выполнения программы (прогресс сообщает backend — GRBL, FluidNC и эмулятор все
  считают его в системе рабочих координат).
* **Пуск / Пауза / Продолжить / Abort** зеркалят состояние контроллера; в нижней
  строке показаны текущая строка, оценка оставшегося времени и последние сообщения.
* Диалог **Редактор** (кнопка карандаша) редактирует загруженную программу на месте
  и перезагружает её при Сохранить; куб ориентации выбирает стандартные виды,
  перетаскивание/зум двигают сцену, переключатель проекции меняет
  перспективу/ортографию.
* **Заготовка** загружает сетку STL/OBJ вокруг детали для контекста.

## 7. Панель FILES

Три источника (при подключении к FluidNC): **файлы хоста** (заперты в
`CNC_UI_FILES_ROOT`), **флэш контроллера** и **SD-карта**. Панель показывает
свободное/занятое пространство отображаемой файловой системы, размеры файлов в
списке, а при отсутствии или неподключённости SD-карты — её статус на месте
списка файлов. Навигация, загрузка/скачивание, mkdir/переименование/перемещение/
копирование/удаление работают одинаково для всех трёх источников.

## 8. Панель MACROS

Создание, редактирование, удаление именованных G-code макросов с метаданными
вызова для каждого контроллера (например `M650` для LinuxCNC-подобных бэкендов,
именованное событие для FluidNC). База данных поставляется **с заранее
загруженными примерами Rosetta**, чтобы панель не была пустой при первом запуске:

| Макрос | Назначение |
|---|---|
| Массив отверстий | генеративный прямоугольный массив с параметрами |
| Ноль Z (простой щуп) | ощупывание рабочего нуля `G38.2` + `G10 L20` |
| 3D-обмер и привязка | измерение угла/кромки заготовки и привязка траектории (Transform поворот+перенос) |
| Запекание G41/G42/G40 (GRBL) | запуск запекания коррекции на радиус (Transform phase D) |
| Глубокое сверление (простые перемещения) | цель подмены G83/G73 для grbl/fluidnc |

Канонические источники этих примеров — YAML-файлы Macro-IR в `config/macros/`;
пресеты подмен лежат в `config/rosetta.yaml` и в таблице `rosetta_settings`
(G83/G73 → макрос прерывистого сверления для grbl и fluidnc). Выполнение макросов
через движок Rosetta запланировано; сегодня панель управляет определениями и
метаданными.

## 9. Журнал сообщений

Нижняя строка показывает последнюю аварию/сообщение; панель (иконка списка)
открывает полную историю с фильтрами по серьёзности/источнику, календарём
диапазона дат, поиском, сортировкой и постраничностью, плюс «копировать
видимое» / «сохранить как текст». Записи сохраняются в базе SQLite между
перезапусками.

## 10. Настройки

Кнопка шестерёнки открывает настройки интерфейса: **тема** (тёмная, светлая,
зелёная, серая) и **язык** (English, Русский, 中文, فارسی). Выбор раскладки —
высоты колонок и панелей — запоминается для каждого браузера.

## 11. Клавиатура и доступность

Пока панель JOG в фокусе: стрелки управляют X/Y, PageUp/PageDown — осью Z,
удерживайте `Ctrl` для непрерывного режима; каждый элемент управления имеет
стилизованную подсказку и доступную метку на активном языке.

## 12. Устранение неполадок

* **«GET response: missing header terminator»** при просмотре файлов FluidNC —
  исправлено в текущих сборках (парсер теперь принимает LF-only HTTP-ответы);
  обновите приложение, если всё ещё видите это.
* **Станок не обнаружен** — убедитесь, что контроллер в той же сети /24, или
  добавьте его ручным повтором обновления; устройства только-Telnet
  подтверждаются через WebSocket после `$ESP120`.
* **Траектория не подсвечивается при пуске GRBL** — проверьте рабочий ноль:
  прогресс считается в системе рабочих координат активной WCS.
* **Веб-интерфейс требует вход** — кто-то запустил `cnc-web` с переменными
  `CNC_UI_AUTH*`; снимите их (или `CNC_UI_AUTH=off`) для открытого использования.

Подробности API и архитектуры: README проекта и `docs/`.
