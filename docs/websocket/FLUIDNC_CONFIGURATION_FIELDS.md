# Параметры FluidNC, полезные для интерфейса

Ответ `$$` содержит несколько групп настроек, которые можно использовать для отображения конфигурации и предварительной валидации команд:

| Настройки | Значение | Возможное применение |
|---|---|---|
| `$110–$115` | Максимальная скорость X/Y/Z/A/B/C, единиц/мин | Ограничивать скорость Jog и показывать предел оси. Для A/B/C единицы могут быть угловыми. |
| `$120–$125` | Ускорение X/Y/Z/A/B/C | Показывать настройки разгона; в будущем использовать для оценки времени перемещения. |
| `$130–$135` | Максимальный ход X/Y/Z/A/B/C | Показывать рабочий ход и проверять целевые координаты. Это длина диапазона, а не обязательно координата максимума относительно рабочего нуля. |
| `$100–$105` | Шаги на единицу для X/Y/Z/A/B/C | Диагностика настройки шаговых двигателей; напрямую для UI обычно не требуется. |
| `$30`, `$31` | Максимальные и минимальные RPM шпинделя, если прошивка их выдаёт | Ограничивать скорость шпинделя и задавать пределы регулятора. |
| `$20`, `$21`, `$22`, `$23` | Soft limits, hard limits, homing enable и направление homing | Отображать возможности и состояние настроек безопасности; не считать их подтверждением наличия или исправности концевиков. |

Для ограничения заданной скорости имеет смысл добавить `max_velocity` в `AxisConfiguration`, заполнить его из `$110–$115` и валидировать пользовательский ввод на backend. UI-ограничение полезно для удобства, но не заменяет backend-проверку и ограничения самой прошивки. При согласованном движении по нескольким осям ограничение скорости зависит от вклада каждой оси в траекторию, поэтому нельзя безусловно применять к общей подаче минимум скоростей всех осей.

Для полноценного расчёта диапазонов позиционирования пригодятся также минимальные координаты осей, если конкретная версия FluidNC предоставляет их через `$`. Имеющиеся `$130–$135` сами по себе сообщают только максимальный ход. Параметры, отсутствующие в ответе `$$`, следует оставлять неизвестными (`None`), а не подставлять догадки.
