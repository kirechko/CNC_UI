# План выделения `cnc_core`

Цель: вынести предметную модель станка, CNC API и адаптеры в независимый Rust-крейт. Сохранить существующий HTML/JS и оба интерфейсных моста — Tauri Commands и Axum Routes. Не начинать миграцию на Leptos и не менять UI в рамках этого плана.

## Этап 1. Зафиксировать границы и базовое состояние

- Проверить текущую сборку и тесты: `cargo check --locked --all-targets` и `cargo test --all-targets`.
- Зафиксировать текущие точки интеграции: `CNCController`, `LinuxCncApi`, адаптер эмулятора, GRBL, Tauri-команды и Axum-маршруты.
- Определить, что входит в ядро: типы и трейты CNC API, общая ошибка, адаптеры и не зависящие от UI сервисы.
- Исключить из ядра Tauri, Axum, DOM/JavaScript и UI-специфичные модели ответа.

**Результат:** зафиксированные критерии миграции и зелёная исходная проверка.

## Этап 2. Создать крейт `cnc_core`

- Добавить отдельный crate, используя существующую версию Rust Edition и минимальный набор зависимостей.
- На первом шаге перенести типы API и трейт `LinuxCncApi` из `src/cnc_api.rs`.
- Сохранить публичные имена и семантику типов, чтобы изменения мостов были минимальными.
- Написать или перенести unit-тесты типов и общих правил API.
- Не включать в `cnc_core` код, которому нужны Tauri, Axum или GTK.

**Результат:** `cnc_core` собирается и тестируется независимо от UI-слоёв.

## Этап 3. Перевести приложение и эмулятор на общий API

- Добавить `cnc_core` как зависимость существующего приложения.
- Заменить локальные определения и `#[path]`-подключения общего API импортами из `cnc_core`.
- Перевести на новые типы контроллер, debug-адаптеры, GRBL-адаптер и адаптер Unix-сокета.
- Сохранить текущие Tauri-команды, HTTP-маршруты, JSON-поля и поведение веб-интерфейса.
- Проверить, что бинарник эмулятора и приложение используют одни и те же типы, без дублирования.

**Результат:** единая модель API используется всеми процессами приложения.

## Этап 4. Перенести адаптеры с явными границами

- Переносить адаптер эмулятора и GRBL по одному; для каждого сохранить существующий протокол и обработку ошибок.
- Проверить, что адаптеры зависят от CNC API, но не от UI-мостов.
- Оставить сетевые обработчики Tauri/Axum тонкими: валидация транспортного ввода, вызов сервиса/API, преобразование результата в ответ.
- Не переносить сервер Axum или обработчики Tauri в `cnc_core`.
- Решить отдельно, нужно ли включать runtime/состояние эмулятора в этот крейт: это не обязательная часть первого выделения API и адаптеров.

**Результат:** адаптеры можно использовать без запуска Tauri или Axum.

## Этап 5. Проверить совместимость и завершить миграцию

- Добавить тесты контракта для общих запросов и статусов, используемых обоими мостами.
- Проверить сборку всех targets, unit-тесты, запуск web-режима и Tauri-приложения с эмулятором.
- Убедиться, что HTML/JS продолжает работать без изменения существующих API-маршрутов и Tauri-команд.
- Проверить `cargo tree` и удалить дублирующие определения, старые импорты и ненужные зависимости только после успешной проверки.
- Отдельным коммитом зафиксировать миграцию, чтобы откат не затрагивал изменения UI.

**Критерий готовности:** `cnc_core` не зависит от Tauri/Axum/GTK; оба текущих интерфейсных моста используют его API; сборка, тесты и сценарии запуска проходят.
